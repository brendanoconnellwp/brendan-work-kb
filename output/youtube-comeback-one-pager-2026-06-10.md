# What I’ve Been Building Lately

> A quick reset after being behind on content: I’ve been doing a lot less “making videos about tools” and a lot more building the memory systems, CMS experiments, agent workflows, and reusable processes behind the scenes.

## 1. A public second brain for AI + web systems

I’ve been building a Git/Obsidian knowledge base that now has **45 articles across 11 topic areas** — AI agents, WordPress, Cloudflare, design-to-dev, Team RAG, agency ops, tooling, and practical implementation frameworks.

The goal is not to hoard notes. It’s to turn research, messy conversations, and build notes into reusable frameworks, diagrams, workflows, and video ideas.

## 2. Hermes is becoming part of the operating system

A big part of what I’ve been exploring is **Hermes as a persistent agent environment**, not just a chatbot window.

That includes:

- persistent memory across sessions
- session search over past chats
- skills as reusable procedural memory
- cron jobs / scheduled research digests
- LLM wiki workflows for turning chats into durable notes
- Mnemosyne-style memory: capture, recall, synthesize, and reuse context over time

The useful question is: **what happens when the assistant can remember the work, search the history, update the wiki, and come back tomorrow with context?**

## 3. I’m going deeper on WordPress → modern CMS workflows

WordPress is still central, but I’m also testing where modern CMS stacks make more sense:

- Astro + Cloudflare Pages / Workers
- Sveltia CMS for Git-backed editing
- Keystatic for structured content workflows
- TinaCMS for visual/headless editing patterns
- EmDash CMS as a Cloudflare/Astro-native “spiritual successor” to parts of WordPress
- safer plugin models, structured content, and agent-operable CMS workflows

The useful question is not “WordPress vs Jamstack.” It’s: **what stack gives the right editing experience, performance, maintainability, and support model?**

## 4. I’m turning AI agents into practical workflows, not demos

A lot of my recent research has been around where agents actually help:

- Claude Code / Codex for supervised development
- Figma MCP and Figma Console MCP for design-to-dev and design-system workflows
- n8n for agency operations
- Team RAG, ingestion, permissions, and access control
- agent evals, monitoring, KPIs, and human-in-the-loop patterns
- workflow audits before automation

The theme: don’t start with “add AI.” Start with the broken workflow, then decide if an agent, automation, RAG system, CMS change, or boring process fix is actually the right move.

## 5. I’m trying to make my own process repeatable

A lot of this came from a personal frustration: I keep doing similar strategy/rebuild/automation work, but each project feels too custom.

So I’ve been turning my own messy process into repeatable steps:

1. intake / raw context
2. current-state audit
3. outside-in research
4. strategy synthesis
5. copy / spec / wireframe
6. visual or workflow directions
7. build plan
8. implementation + verification

This is also how I want to make more useful content: less tool hype, more real process.
